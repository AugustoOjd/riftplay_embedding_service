## Decisiones

- **Request de `/search` con filtro `documents`** (identidad o `prefijo/*`), además de
  `query` y `k`. Se descartó el request mínimo porque el agente de chat va a querer preguntar
  solo por errata o por un set, y agregarlo después es un cambio de contrato.
- **Respuesta con la cita completa** (`id`, `title`, `source_url`, `rule`, `score`) y `model`
  en la raíz. Se descartó traer fragmentos vecinos: duplica tokens contra `token_usages`.
- **Errores por código HTTP** (400/401/502/503; vacío = 200 con `results: []`). Se descartó
  "siempre 200 con campo error": Python necesita distinguir bug propio de caída para hacer
  fail open, y esconde fallas en los logs.
- **Red privada de Railway + Bearer secreto.** Se descartó solo red privada: un dominio
  público puesto por error dejaría `/search` abierto y gastando crédito de OpenAI.
- **Misma base, schema `rules` propio.** Se descartó una base aparte (otro Postgres que
  pagar) y el schema `public` (sumar tablas a `ingest_owned_tables()` y posible choque con la
  tabla vieja de la `0001`).
- **Stack igual a ingest + `pgvector-go`.** Se descartó pasar el vector como texto: serializar
  1536 floats a mano y que sqlc lo vea como string.
- **Tres tablas: `documents`, `fragments` (HNSW coseno) y `sync_runs`.** El historial de
  corridas en tabla y no solo en slog, para poder tener un dashboard como el de ingest.
- **River para el cron**, con schema `river_embedding`. Se descartó la goroutine con ticker
  (corre doble con dos réplicas y no reintenta) y el cron de Railway (dos servicios, sin
  reintento).
- **PDF con `pdftotext`, pero spike primero.** Se descartó la librería Go pura: peor
  extracción con columnas y parsea un PDF de 17,5 MB dentro del proceso.
- **Cliente de embeddings propio con `net/http` detrás de una interfaz `Embedder`.** Se
  descartó el SDK de OpenAI: un SDK grande para un solo endpoint y ata a OpenAI cuando la
  alternativa es Voyage.
- **Agente de revisión en Go**, con loop de tools propio sobre Anthropic. Se descartó
  ponerlo en la API Python: Go tendría que exponer sus tools como endpoints de admin, el
  acoplamiento que la opción B quería evitar.
- **El agente nunca borra:** allowlist chica, la versión nueva queda pendiente y `/search`
  sirve la aprobada. Se descartó la autonomía amplia porque el texto scrapeado puede traer
  inyección de prompt.
- **Sin respuesta, nunca expira:** se sigue sirviendo la versión anterior con recordatorio
  diario. Se descartó expirar y aplicar algo, porque un Core Rules nuevo legítimo podría
  quedar descartado sin aviso.
- **Golden queries en un archivo versionado.** Se descartó que las genere el agente: se
  evaluaría con preguntas escritas sobre el mismo texto que ve y no detectaría un parseo roto.
- **Tests de integración contra Postgres real con pgvector.** Con fakes no se prueba la
  transacción de reemplazo ni la búsqueda por coseno.
